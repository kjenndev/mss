# MSS Stream Manager integration

The integration is disabled unless every `MSS_STREAM_MANAGER_*` value is valid. It does not create, reassign, or rotate Platform channels or keys. Ordinary MSS and Platform watch/chat/admin flows are unchanged.

Generate a dedicated Ed25519 key pair and a separate random (at least 32-byte) introspection token. Keep the private key and token only in owner-readable environment storage. Configure MSS with its private key, exact MSS issuer origin, exact Platform browser origin, `streaming-platform` audience, and an explicit JSON map from owned MSS artist IDs to their already-created Platform channel names. Configure Platform with the matching public key, exact MSS browser origin, exact MSS introspection endpoint, the same dedicated token, the inverse channel-to-artist map, and an explicit `MSS_DELEGATION_INGEST_URL` such as `rtmps://ingest.example/live`. The ingest URL must use RTMP/RTMPS, end at `/live`, and contain no credentials, query, or fragment. Do not reuse either application's login/JWT/admin secrets.

Activation order is Platform route/config first, then MSS. Verify framing/CSP at the deployed origins before enabling. Missing or mismatched configuration intentionally shows “Stream Manager is not configured” and grants no player, chat, or OBS access. Delegated grants expire after 90 seconds; the nonce-bound parent refresh and admitted socket atomically replace the grant and media capability without remounting the frame or leaving chat. Platform re-introspects on join, refresh, playback renewal, socket revalidation, and the media worker's two-second authorization sweep. Backchannel failure terminates only delegated access and clears its secrets.

MSS keeps a bounded, expiry-purged in-process `jti` registry that maps issued grants to server-only session tokens, so introspection performs one exact indexed session-token lookup rather than scanning a user's sessions. Restarting MSS revokes every outstanding delegated grant. Multi-instance deployments must use sticky routing for issuance and introspection (or replace this registry with a shared bounded server-side store); capacity exhaustion denies new grants.

The parent acknowledges each preview request ID exactly once. Automatic requests defer to an existing MSS audio selection; an explicit Return to preview closes the persistent audio player and confirms its iframe unmounted before acknowledgement. Selecting MSS audio later stops manager video; chat autojoin alone does neither. Grant refresh updates the existing child socket and playback authority without remounting the valid frame or chat. Each renewal has a nonce- and generation-bound acknowledgement deadline, and the next renewal is scheduled from the authenticated server expiry returned with the accepted grant. A stale grant response, refresh acknowledgement, or Play replay cannot mutate a newer artist/frame lifecycle. Timeout, denial, disconnect, or authorization loss clears credentials and removes the iframe until explicit retry. OBS credentials are released only by the successful delegated socket join acknowledgement; the earlier HTTP context response contains no key. Server and key are independently masked, revealed, copied, and cleared. Grant signing uses the normal advisory mutation lock and one transaction with the documented user → session → artist row-lock order, then signs only the re-read current values. Introspection resolves the grant through a bounded in-memory registry to one exact session-token query; capacity is fixed and a process restart intentionally revokes all outstanding grants.

No live trust, mappings, credentials, database rows, or channels are installed by this repository change.

OBS stream key is the complete Platform-provided `channelName?key=actualSecret` publish name, with each component URI-encoded; copy it directly alongside the separate server URL. Do not prepend the channel again. The complete value remains masked until revealed and is cleared on authorization loss. Automatic manager preview leaves chat connected and reserves the same video area; chat sits to the right on desktop and below on narrow frames. Internal `mss-manager-watch-*` messages retain their existing nonce/source/origin and replay checks.

## Automatic manager preview

The manager preview starts muted after delegated membership and the nonce-bound parent audio acknowledgement. It shows an offline placeholder when publishing stops and reconnects automatically after socket readmission. The manager has Unmute/Mute, not separate Play/Pause; these controls never start or stop OBS or publishing. Ordinary Platform watch/embed controls are unchanged.

An existing MSS library audio selection takes priority over automatic preview. Automatic requests do not close that audio; Return to preview is the explicit switch, which removes the audio iframe before acknowledging playback. A later audio selection stops preview and invalidates pending acknowledgements; live status and reconnect events cannot steal it back. Reconnected/offline-to-live preview starts muted again. Revoked authority is terminal until explicit retry; grants, nonce/source/origin checks and replay cleanup remain in force. Preview/chat dimensions retain the previous layout, including the mobile header allocation.
